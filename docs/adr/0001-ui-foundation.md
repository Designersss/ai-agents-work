# ADR-0001. Тёмный UI-каркас AIMock

**Статус:** предложено в draft PR. **Связано с** #2, #3, #4, #5, #6.

## Контекст

Проверенный эксперимент Spike PR #1 содержит рабочий, но временный UI с реальным AI-запросом. Для основной платформы пользователь предложил идти последовательно: сначала единый архитектурный master issue и связанные задачи, затем дизайн, левое меню, шапка и «Обзор». Существующий светлый дизайн больше не является обязательным; приоритет — скорость разработки на бесплатных интегрируемых компонентах.

## Решение

- Новая ветка от `main`, **не** от экспериментального PR #1. Spike оставляем нетронутым до миграции проверенных подсистем.
- Next.js + TypeScript (strict) + Tailwind CSS 4 + компоненты в соглашениях shadcn/ui; интерактивные примитивы — открытые Radix UI, иконки Lucide.
- Только тёмная тема на первом этапе. Токены цветов/радиусов централизованы в CSS; акцентный зелёный используется умеренно.
- Переключатель Personal/Company и 7/30 дней функциональны на **изолированных демонстрационных данных**; нет сетевых запросов, подписок, кошельков и искусственных AI-ответов.
- Пустые состояния на личном пространстве; непостроенные разделы меню помечены как недоступные.
- Архитектуру API (NestJS/Better Auth/PostgreSQL/AI SDK) присоединяем после UI-приёмки через отдельные issue и ADR.

## Отвергнутые альтернативы

1. Переносить экспериментальный Next.js/NestJS из PR #1 целиком: временная модель расчёта средств неприемлема для production.
2. Копировать страницы из design-agents пиксель в пиксель: излишняя трудоёмкость без подтверждённой пользовательской ценности.
3. Использовать платные dashboard templates: нарушает принцип бесплатной коммерческой интеграции.
4. Притворяться, будто временные цифры получены через API: подрывает доверие к продукту.

## Критерии принятия

Сборка, lint, typecheck, тесты fixtures/диапазона, ручной review desktop/mobile и явное согласие владельца. До этого PR остаётся draft.
